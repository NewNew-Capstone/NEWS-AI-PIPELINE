# 3주 최종발표 대응 실행 계획 (기능1·2 범위 재정의)

## 1) 목표 및 범위 고정

### 목표
- 넓은 기능 확장보다 **작동하는 데모 + 설명 가능한 결과**를 우선한다.
- 최종 발표에서 아래 2개 화면을 완성 상태로 시연한다.
  - 기능2 비교 리포트 화면 1개
  - 기능1 설명가능성(근거 문장 중심) 화면 1개

### 이번 발표 범위(In)
- 기능2: 이슈 1~2개, 국가 3개(KR/US/CN), 영상 30~50개 수작업 큐레이션.
- 기능1 추천: 유사 추천 + 반대 관점 추천(휴리스틱 2트랙).
- 설명가능성: 점수 숫자만이 아니라 근거 문장/표현을 메인으로 노출.

### 발표 범위 밖(Out)
- 엔티티 기반 자동 추천 고도화.
- 대규모 모델 교체/재학습/아키텍처 재설계.

---

## 2) 기능2 데이터 우선 완성 전략

### 큐레이션 기준
- 이슈 선정: 국제 이슈 1~2개(3개 국가에서 모두 영상 확보 가능한 주제).
- 국가/언어 기준: KR/ko, US/en, CN/zh.
- 채널 균형: 특정 채널 편중 방지(상위 채널 집중도 기록).
- 제외 기준:
  - `country_code`, `language`, `status` 누락
  - `video_id` 누락
  - 이슈 미연결 (`PART_OF` 없음)

### 적재 품질 게이트 (필수)
- `Video.country_code`, `Video.language`, `Video.status` 필수.
- `(Video)-[:PART_OF]->(Issue)` 필수.
- `(Video)-[:HAS_ANALYSIS]->(AnalysisResult)`는 가능한 범위에서 연결, 미완료는 원인 로그.

### 비교 지표 (리포트 고정 항목)
- 영상 수
- 조회수
- 평균 bias_score
- tone_label 분포
- 채널 편중도 (HHI 또는 상위 채널 점유율)

### 빈 그래프 원인 분류 로그
- source 속성 누락
- 분석 미완료(`HAS_ANALYSIS`/`opinion_score` 부족)
- 후보 부족(동일 이슈 내 타국가 데이터 부족)

---

## 3) 기능1 완성 전략 (추천 + 설명가능성)

### 추천 규칙 고정
- 유사 추천: 임베딩 코사인 유사도 상위.
- 반대 관점 추천: 주제 유사 + `tone_label` 상이 + `bias_score` 차이 임계치 이상.

### 설명가능성 화면 고정 요소
- 근거 문장 하이라이트.
- 점수 분해(`opinion/emotion/fact`) + 문장 근거 매핑.
- “왜 주관적 판단인지”를 문장 단위로 설명.
- 추천 카드에 추천 이유(톤 차이/점수 차이/근거 키워드) 표시.

---

## 4) 3주 실행 로드맵

### 1주차 — 데이터·파이프라인 안정화
- [ ] 이슈 1~2개 확정.
- [ ] 30~50개 큐레이션 완료(국가별 균형).
- [ ] 적재/분석 재실행.
- [ ] 스키마 필수값 누락률 0% 달성(`country_code/language/status`).
- [ ] 기능2에서 최소 1개 이상 비교쌍 생성 확인.

### 2주차 — 화면·지표 완성
- [ ] 비교 리포트 화면 1개 완성(5개 지표 고정).
- [ ] 기능1 설명가능성 화면 완성.
- [ ] 추천 샘플셋(유사/반대) 정리.

### 3주차 — 검증·발표 패키징
- [ ] E2E 리허설(수집→분석→비교→설명).
- [ ] 실패 케이스 대응 플로우 준비.
- [ ] 교수님 피드백 대응 슬라이드 완성(강점/한계/향후과제).

## 5) 테스트/검증 기준

### 데이터 품질
- [ ] `country_code/language/status` 누락률 0%.
- [ ] `HAS_ANALYSIS` 연결률 목표(예: 90%+) 달성.

### 기능2
- [ ] 선택 영상 기준 related/edges 생성.
- [ ] 국가별 지표 계산 일관성(동일 입력 재조회 시 동일 집계).

### 기능1
- [ ] 유사 추천 10건 수기 평가(타당/부분타당/부적합).
- [ ] 반대 관점 추천 10건 수기 평가.

### 설명가능성
- [ ] 점수와 근거 문장 연결 정확도 점검 체크리스트 통과.

---

## 6) 독창성/약점 대응 발표 문구 가이드

### 독창성 3축
1. 설명가능성 중심 UX: 점수보다 근거 문장과 표현 중심 설명.
2. 도메인 차별성: 한국어 유튜브 뉴스 자막(구어체) 적용.
3. 국가별 비교 실동작: 좁은 범위라도 실제 동작 데모 제시.

### 약점 대응
- KNU + FastText + Qdrant 선택 이유:
  - 경량, 재현성, 리소스 제약에서 실험 반복 용이.
- 오탐 가능성은 명시적으로 인정.
- 잘 동작한 사례 5~10개를 함께 제시.
- emotion_score 저값 사례의 해석 가이드 제공(모듈 한계/데이터 특성/보완 방향).

- [ ] 향후 과제 분리 슬라이드 1장(엔티티 자동 추천, 모델 고도화 등).
