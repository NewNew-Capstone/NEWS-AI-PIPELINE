# 국가별 영상 비교분석 초안 (v0.2)

## 1. 목적
- 분석 목적: Neo4j 그래프 DB 기반으로 동일 이슈에서 국가별 관심도, 톤, 확산 구조 차이를 비교 가능한 형태로 정리한다.
- 비교 질문(핵심 2~3개):
  - 같은 이슈에서 국가별 영상 생산량과 소비량(조회수) 차이는 어떻게 나타나는가?
  - 국가별 톤 분포 및 평균 편향 점수는 어떤 패턴을 보이는가?
  - 어떤 채널이 국가별/국가 간 이슈 확산의 중심 역할을 하는가?

## 2. 범위
- 기간: 최근 7일 (초기 테스트 기본값)
- 대상 국가: KR, US, JP
- 키워드/이슈: 2개 이슈 키워드 (예: 우크라이나, 반도체)
- 데이터 출처(Neo4j 그래프): AuraDB 인스턴스(`neo4j` DB), 현재는 샘플 노드/관계 기준으로 검증 완료

## 3. 데이터 모델 요약
- 사용 노드:
  - `Video`
  - `Channel`
  - `IssueCluster`
  - `AnalysisResult`
- 사용 관계:
  - `(Video)-[:PUBLISHED_BY]->(Channel)`
  - `(Video)-[:BELONGS_TO]->(IssueCluster)`
  - `(Video)-[:HAS_ANALYSIS]->(AnalysisResult)`
- 주요 속성(viewCount, publishedAt, sentimentScore 등):
  - Video: `video_id`, `title`, `country` 또는 `country_code`, `viewCount`, `published_at`
  - Channel: `channel_id`, `channel_name`
  - IssueCluster: `issue_id`, `name`
  - AnalysisResult: `analysis_id`, `overall_bias_score`, `tone_label`, `status`

## 4. 비교 지표 정의
- 지표1: 영상 수
  - 정의: 국가/이슈/기간 필터 후 `count(DISTINCT Video)`
- 지표2: 총 조회수 / 평균 조회수
  - 정의: `sum(viewCount)`, `avg(viewCount)`
- 지표3: 감정(톤/편향) 점수 평균
  - 정의: `avg(overall_bias_score)` + `tone_label` 분포
- 지표4: 주제 분포 Top N
  - 정의: `IssueCluster.name` 빈도 기준 상위 N개
- 지표5: 채널 편중도(상위 3채널 비중)
  - 정의: 국가/이슈별 상위 3개 채널 조회수 합 / 전체 조회수

## 5. 분석 방법
- 필터 조건:
  - 기간: 최근 7일
  - 국가: KR, US, JP
  - 이슈: 키워드 2개
  - 제외 규칙: 국가 미상, 조회수 미상, `AnalysisResult.status=FAILED`
- 집계 로직:
  - 대안 1(룰 기반): 영상 수/조회수/bias/tone/채널비중 집계
  - 대안 2(그래프 기반): 중심 채널(가중 degree), 커뮤니티 proxy, 브리지 채널 탐색
- 접근 방식 대안(상세):
  - 대안 A (비KG 룰 기반 Baseline):
    - RDB/JSON 중심 집계, 구현이 빠르고 설명이 쉬움
    - 한계: 확산 경로/브리지 채널 등 관계 정보 해석이 약함
  - 대안 B (KG 중심 구조 분석):
    - `Video-Channel-IssueCluster-AnalysisResult` 관계 기반 구조 분석
    - 장점: 누가 이슈를 연결/증폭했는지 설명 가능
    - 한계: 라벨/관계 품질과 스키마 일관성에 민감
  - 대안 C (하이브리드, 권장):
    - 대안 A의 KPI 집계 + 대안 B의 구조 인사이트를 통합
    - 장점: 숫자 비교와 구조 해석을 동시에 제공 가능
- 정규화 방식(필요 시 인구/채널수 보정):
  - 1차: 원시 지표 비교
  - 2차(확장): 국가별 활성 채널 수 또는 국가별 표본수로 보정

## 5-1. KG 사용/미사용 비교 및 채택 검증
- KG 미사용(비KG 집계)일 때:
  - 가능한 것: 국가별 수치 비교(영상 수, 조회수, 평균 점수)
  - 어려운 것: 확산 경로, 브리지 채널, 네트워크 구조 차이 설명
- KG 사용 시:
  - 추가 가능한 것: 중심 채널 식별, 국가 간 브리지 탐지, 구조 기반 해석
  - 기대효과: \"얼마나\"뿐 아니라 \"어떻게 퍼졌는지\"를 설명 가능
- KG 채택 검증 방식:
  - 동일 데이터셋으로 대안 A/B/C 병렬 실행
  - 공통 평가지표 비교: `accuracy`, `interpretability`, `runtime`, `reproducibility`, `ops_cost`
  - 채택 판단:
    - A 우세 + 구조 인사이트 가치 낮음 -> A 채택
    - A 빠르나 설명력 부족 + B 구조 인사이트 유의미 -> C 채택
    - B 품질 불안정(라벨/관계 부족) -> A 유지 + KG 품질 개선 후 재평가

## 6. 초기 테스트 결과 (소규모)
- 테스트 조건:
  - 스모크: 1이슈 + 2국가 + 3일
  - 본 테스트: 2이슈 + 3국가 + 7일
  - 재현성: 동일 조건 2회 재실행
  - 품질: 수작업 검증셋 30~50건은 향후 수집
- 결과 표:

| approach | accuracy | interpretability | runtime | reproducibility | ops_cost | total | notes |
|---|---:|---:|---:|---:|---:|---:|---|
| rule_based | pending | 4.5 | 4.5 | pending | 4.6 | pending | 실데이터 미적재 상태 |
| graph_based | pending | 3.8 | 3.5 | pending | 3.6 | pending | 실데이터 미적재 상태 |

- 해석 요약(3~5줄):
  - 환경/연결/스키마 적용 및 샘플 그래프 생성까지는 정상 완료되었다.
  - 대안 1/2 실행 프레임과 출력 템플릿은 고정되어 재실행 가능하다.
  - 현재는 실데이터가 충분히 적재되지 않아 정확도/재현성 점수는 `pending`으로 유지한다.
  - 실데이터 적재 후 동일 템플릿으로 즉시 비교 결과를 업데이트할 수 있다.
- 데이터 품질 이슈:
  - 현재 데이터 볼륨 부족(샘플 노드/관계 중심)
  - `country` vs `country_code` 표준화 필요
  - `published_at` 형식 및 `viewCount` 누락 처리 정책 확정 필요
