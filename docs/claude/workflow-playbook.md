# Workflow Playbook (Token-Saving)

## A. 세션 운영 원칙
- 한 세션 = 한 작업(기능 1개 또는 버그 1개)
- 큰 작업은 계획 먼저, 실행은 나중
- 잘못된 방향이면 즉시 중단 후 계획 재수립

## B. 컨텍스트/토큰 절약 규칙
- 루트 문서는 짧게, 상세는 분리 파일 참조
- 무거운 데이터 처리는 스크립트로 오프로드하고 결과만 요약
- 불필요한 도구/연결은 비활성화
- 대화 길이가 길어지면 압축/정리 후 다음 작업 진행

## C. 실전 실행 루프
1. Plan: 파일/영향 범위/검증 방법 확정
2. Implement: 최소 변경 단위 1개 적용
3. Verify: 테스트/린트/로그 확인
4. Record: TODO/문서 업데이트
5. Repeat

## D. 실패 방지 체크리스트
- 수정 대상 파일이 요구사항과 직접 연결되는가?
- BC 경계를 침범하는가?
- 재사용 가능한 결과(요약/점수/스냅샷)를 남기는가?
- 상태값/버전/근거가 누락되지 않았는가?

## E. 유지보수 룰
- 새 규칙은 루트에 1~2줄, 상세는 이 파일 또는 별도 문서에 확장
- 팀 공통 패턴은 반드시 문서화 후 커밋
